# Public data update feed

The public `/data-updates/` page combines version notes bundled from the published changelog with the data feed. Version notes have date precision; data timestamps represent GIDS publication time. Coverage numbers come from the current published surveillance summary. Curve points are the sum of per-jurisdiction record_count values for jurisdictions with data; geographic levels can overlap and these are not counts of distinct cases. The data feed index contains counts of retained publication batches, not observation counts. The page reads `site-data/updates/latest.json` and monthly UTC files from the existing Pages data Worker and R2 bucket. The feed reconciler projects only `publish_dirty` markers acknowledged by completed export tasks. Surveillance, Situation, literature and knowledge are independent event types. A marker denotes publication of a scope, not the number of observations or source publication time. Missing historical markers cannot be reconstructed as precise events. Only approved scope identifiers and publication times are public; raw task inputs, logs and errors are never included.

`scripts/publish_public_updates.py` reads the database and regenerates the feed. It uploads changed monthly files before the index; conditional writes detect overlapping writes, and a local lock serializes runs on the publisher host. Run the reconciler on one host only; a local lock does not coordinate multiple hosts. A later run retries after an error. Reconciliation runs separately from publication tasks, groups duplicate scopes in the database, uses a read-only transaction, and limits each PostgreSQL statement to five seconds; a failed or slow reconciliation retries on the next timer run. It does not delay the completion of publication tasks. Browser reads are limited to the selected month and the existing published surveillance summary; the page does not load the research index. `globalid-public-updates.timer` schedules this every minute once the included systemd units are installed and enabled by the normal installer. The page checks once a minute while open. JSON is served with `no-store`.

Deploying requires the updated Pages Worker and site templates, an R2 binding to the existing data bucket, and the reconciler timer. The installer substitutes the same project/user placeholders used by the other units. Check the initial reconciliation and public JSON responses before enabling the timer. The changes here do not themselves deploy the site, upload a feed, install units, or enable a timer.

The page filters an inclusive UTC date range and draws one bar per day for the records that match the selected type. It still reads only the monthly archives that intersect that range. Event times are displayed in the viewer's local timezone. Changing the range hides the previous records while a newly requested archive is loading. Index and archive failures are tracked separately, previously loaded records remain visible during a failed refresh, and requests time out after 15 seconds. An index retry starts 60 seconds after the previous request completes, avoiding overlapping responses.

For an existing installation, render units with `scripts/install_systemd_services.sh --dry-run`, install only `globalid-public-updates.service` and `globalid-public-updates.timer` using the existing project and service user, then run `systemctl daemon-reload`. Start `globalid-public-updates.service` once and inspect its journal and the public index/month responses before `systemctl enable --now globalid-public-updates.timer`. The oneshot service loads the latest Python code on each run; this feature does not require restarting the scheduler, publication worker or database. Standalone script invocations need the same database and R2 environment supplied by the service's `EnvironmentFile`.
