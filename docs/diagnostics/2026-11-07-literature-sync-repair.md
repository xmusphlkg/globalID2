# 2026-11-07 文献同步修复与验证

本轮使用三个并行子任务完成代码修复，并交叉审查分页接口和历史补采隔离。
验证使用临时测试数据库、现有数据库的只读查询及有限的来源分页探测。
没有重启运行中的 worker、执行历史补采、调整发表门禁或清空审核积压。

## 修复

- Crossref 任一期刊初始请求或后续分页失败时，保存成功记录，但保留旧水位与边界 ID。
  同一游标的请求参数保持一致。期刊级错误进入来源日志和计数；健康检查也识别旧
  `checkpoint.source_errors` 与零错误计数不一致的记录。
- 主题发现 v2 为每个查询/来源保存固定时间窗口及页游标，失败和封顶均可继续。
  查询轮转不会跳过其他查询的时间窗口。PubMed 大窗口拆分，单日超过上游限制时
  保留窗口并报错；不把错误响应、超量记录或不明分页终止当作完成。
- 大于 64 MiB 的发布索引流式校验，保留已有内容规则与跨记录校验，并限制单项和
  总输入大小。新增依赖 `ijson==3.6.0`，已安装到本地 venv。
- 审核容量不足时暂停加速追赶，保留普通定时同步；输出恢复阈值、计数口径及
  必须减少的积压量。阈值低于单批容量时给出配置修正动作。
- 同步和摘要任务仅治理本轮文章，避免每轮扫描全库。受影响证据缺口仍检查全部
  关联文章；显式全库维护保留。局部治理审计不冒充全库积压快照。
- 新增历史期刊补采工具，使用独立来源和游标，复用正常质量门禁、原始证据记录及
  入库事务，不改写实时同步水位。

[补采操作步骤](../RESEARCH_RADAR.md#repair-historical-journal-failures) 逐窗口入队、检查
完成状态并继续下一页。补采仅能遍历上游当前索引中的该时间区间。

旧主题发现断点无法证明历史覆盖，迁移后明确保留未知标记。按发表日期检索仍需
考虑晚到索引；本轮不宣称已经恢复所有过去未采到的主题文章。
