The regional plan was not changed. Evidence is retained under `data/current/mx/regional-audit/` (`requests.json`, `followup-requests.json`, `coverage-requests.json` and exact response bodies).

The SPF hepatitis-A record endpoint is:

`https://odisse.santepubliquefrance.fr/api/explore/v2.1/catalog/datasets/hepatite-a-donnees-declaration-obligatoire/records`

Use bounded JSON pagination or the dataset export API, retain metadata/version timestamps and verify page totals. The complete 40-row filtered response and extent receipt are saved as `FR_hepatite_overseas_all.body` and `FR_hepatite_overseas_extent.json`; the CL package metadata and CSV probe receipts are `CL_ENO_package.json` and `CL_ENO_csv_probe.json`. Population denominators come from the source, not a guessed territorial population. `legionellose-donnees-declaration-obligatoire` also returns structured annual department data, but overseas coverage must be explicitly queried before claiming it supports GP/MQ/GF.

A misleading candidate was explicitly rejected: ODISSÉ dataset `leptospirose-donnees-par-lieu-de-residence-region` has a leptospirosis title but a description about mandatory **TBE** notifications. Its 39 returned records contain only metropolitan region labels, with no GP/MQ/GF territory records. It is not validated as an overseas leptospirosis source. This illustrates why catalog titles alone are insufficient to authorize disease/territory integration.

Priority after the active country work: verify the Chile ENO CSV/dictionary as a bounded historical integration, then CO INS's large municipality archive; SPF hepatitis-A territory rows offer a small, explicit route for GP/MQ/GF. PY/EC need source-access resolution. None of these candidate probes changes existing production data pointers or publishes data.
