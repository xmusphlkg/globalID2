# 主站 JSON 内容与独立界面发布设计

状态：设计草案，2026 年 11 月 12 日。本文定义后续实施范围，不代表功能已部署。现阶段按 Workers Free 的预算设计；实际账户套餐、用量和生产路由需在第一阶段核验。

主站保留 Astro、React 和现有视觉体系，逐步分离内容、样式、模板与发布编排。默认采用 Pages 静态 HTML 与公开 R2 CDN 数据，让常用主站页面不依赖 Worker 请求额度。已有 Papers 动态渲染继续保留，并计入同一账户预算；不将全部主站页面改为请求时渲染。

## 预期行为与边界

| 变更 | 目标发布路径 | 不应触发的工作 |
| --- | --- | --- |
| 已有国家或疾病的观测数据更新 | 导出变化 JSON，提交对应数据通道版本 | Astro、Vite、Pages 部署、正文渲染 |
| 一篇文章正文更新 | 更新该内容记录及受影响的目录、搜索、SEO 投影 | 无关文章渲染、全站界面编译 |
| 主题颜色、字体、间距等兼容样式更新 | 编译独立 CSS，更新对应样式兼容通道 | 内容导出、正文渲染、Pages 部署 |
| 国家页结构或交互更新 | 编译国家页模板与客户端资源，生成受影响的静态页面 | 文献、报告及其他无关页面的正文重建 |
| 新国家、新疾病、新 slug | 发布内容，并更新必要的静态路由、目录和 sitemap | 无关正文重建 |
| 内容 schema 不兼容变化 | 先发布兼容读取器，再迁移内容，最后退役旧契约 | 将不兼容 JSON 直接交给旧客户端 |

“JSON 承载主要内容”不要求所有 HTML 都在浏览器生成。需要被搜索引擎直接读取的正文、标题、canonical、语言链接和结构化数据，仍保留静态 HTML 或已存在的 Worker HTML 投影。

纯静态 HTML 的结构改变，仍需重新生成并部署受影响的 HTML。目标是取消无关内容处理和全量 Astro 渲染，不能同时承诺任意 DOM 变化、所有 HTML 字节不变以及完全不经过动态服务。阶段验收分别记录内容渲染、页面组装、资源编译和部署耗时。

## Worker 额度与请求路径

### 预算依据

截至本次设计核对，Workers Free 的账户级请求限额为每日 100,000 次，UTC 00:00 重置，即北京时间每日 08:00。超限存在请求失败风险；不能假定分成多个 Worker 会得到多份账户额度。[Workers 限额](https://developers.cloudflare.com/workers/platform/limits/#daily-requests)

Pages Functions 按 Workers 计费；未调用 Functions 的 Pages 静态资源请求免费且不限次数。必须在路由层绕开 Functions，在 Worker 中调用 `env.ASSETS.fetch` 不能视作零调用。[Pages 计费](https://developers.cloudflare.com/pages/functions/pricing/)

Workers Paid 当前最低每账户每月 5 美元，包含每月 1,000 万请求和 3,000 万 CPU 毫秒，超额分别按每百万请求 0.30 美元、每百万 CPU 毫秒 0.02 美元计费。Worker 内缓存和 Workers Caching 都不能作为免除请求计数的依据；后者的缓存命中仍按请求计费。此处仅用于方案比较，不假定当前账户已付费，也不把 R2、日志等费用包含在内。[Workers 计费](https://developers.cloudflare.com/workers/platform/pricing/)

### 路由分工

| 请求 | 目标服务 | 新主站路径的 Worker 请求目标 |
| --- | --- | --- |
| 首页、国家、疾病、比较、说明等已生成 HTML | Pages 静态资源 | 0 |
| CSS、JS、字体、图片 | Pages 静态资源或公开 R2 自定义域名 | 0 |
| 公开 JSON 入口、manifest、内容对象 | 公开 R2 自定义域名直读 | 0 |
| 已有 Papers 文章 HTML | 现有 Papers Worker | 按实际请求计入预算 |
| 订阅等动态 API | 保留现有服务 | 单独监测，并计入账户总额 |
| 旧同源 JSON URL | 迁移期保留现有 Worker | 单独统计旧客户端流量 |

建议使用 `static.globalinfectiousdisease.com` 作为公开对象域名，具体名称在域名盘点后确定。它直接连接只含公开投影的 R2 bucket，不挂全域 Worker。不能为了直读而开放可能混有内部资料的现有 bucket；复制公开对象并验证后再切换。`r2.dev` 不作为生产分发入口。

R2 自定义域名支持 CDN 缓存，但 JSON 等类型不能假定默认已缓存。为不可变对象明确配置缓存规则，为可变入口配置独立 TTL，并验证真实响应。[R2 公共访问与缓存](https://developers.cloudflare.com/r2/buckets/public-buckets/)

Pages 的 `_routes.json` 使用必要路径白名单；同时盘点 zone Worker Routes、自定义域名与已有研究路由。Pages 的排除规则无法撤销上游独立 Worker 路由。不要新增覆盖主站 `/*` 的 Worker，也不要让新客户端先访问 Worker 重定向再获取 CDN 对象。[Pages 调用路由](https://developers.cloudflare.com/pages/functions/routing/)

浏览器跨域读取使用公开 GET/HEAD、不携带凭据；配置 CORS、CSP、字体及模块脚本策略。不能添加无必要的自定义请求头导致预检。CORS 改动后验证带 Origin 的请求及缓存更新。[R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)

### 用量模型与保护

每日计费请求估算：

```text
W = 主站访问 × 每次访问经过 Worker 的平均请求数
  + Papers 动态请求 + 订阅等 API 请求
  + 旧客户端兼容请求 + 爬虫及探测请求
```

以下只是假设示例：每天 10,000 次主站访问，每次 6 个 Worker 请求会产生 60,000 次调用；降为 1 个仍为 10,000 次；直读 CDN 可将这部分降至 0。其他服务流量仍须相加。既有统计像素或分析脚本若调用账户内 Worker，也必须计入。

面板同时显示账户总额与各服务用量，Free 按重置窗口统计，Paid 按实际账期统计。预留量由其他服务峰值、爬虫流量和增长余量共同确定，不把全部额度分配给主站。建议预警阈值为 50%、75%、90%，属于可调整的产品策略。

用量采集由现有后端定时任务集中执行，例如每 5 分钟一次，并缓存结果；面板读取后端快照，不能每位管理员刷新都调用 Cloudflare API。显示采样时间、数据来源、延迟、预测与实际的区别。没有权限或指标过期时显示“未知”，不能显示为 0 或健康。

额度紧张时，首先减少可选探测和前端重复刷新，停止扩大动态路由范围。暂停内容发布并不会停止现有访问流量，不能把暂停发布当作额度保护。若 Papers 已占据主要预算，再单独评估付费或静态 HTML 投影；切换前必须实际准备可访问的静态内容，不能仅依赖 fail-open。

## 内容与资源协议

### 各通道独立提交

保留 surveillance、situation、research 的独立发布周期。各通道一份权威可变指针，引用不可变 manifest 和对象。公开 CDN 可以承载只读分发副本，但不能形成第二个可独立推进的权威指针。迁移时由同一发布任务写入和核验副本，分别记录权威提交、分发可见和数据库确认状态。

```text
某内容通道 current.json
  → immutable manifest
    → 按实体或内容记录分片的 JSON

模板清单
  → 支持的内容 schema、DOM 兼容版本
  → 固定版本的 JS 与结构性 CSS

主题兼容入口 theme/compat/v1/theme.css
  → 一个不可变的主题 CSS 版本
```

监测和 Situation 的旧入口保持原有契约。新 CDN 的可变入口初始建议浏览器 TTL 为 0、边缘 TTL 为 30 秒；不可变对象使用长缓存，缺失对象不长时间缓存。30 秒是拟定的可见性目标参数，不是全球同步承诺，须通过实际缓存规则验证。旧客户端的 `cache: no-cache`、入口回退及相对 URL 解析必须专项验证。

新导航固定一次对应通道版本，图表和延迟展开内容继续读取该版本。避免组件各自读取 current，也不通过不断添加随机 query 绕过缓存。常用摘要进入轻量 bootstrap，大图表与全文按需加载，不能为减少请求而下载全站大 JSON。

内容对象包含 schema、身份、语言内容、审定状态、来源和必要展示字段；模板与资源版本不混入正文内容摘要。丰富正文可保留经过发布端清洗的 HTML 片段，普通字段由组件转义。应直接从内容投影生成记录，不再先渲染整篇完整 HTML 再拆回 JSON。

需要静态 SEO 的内容，由同一 JSON 生成受影响页面的 HTML 投影；更新一篇内容可连带更新目录、搜索、feed 和 sitemap，但不要求重新编译全部前端。索引分片及完整性检查按受影响范围执行，全局唯一性等检查使用已验证索引。

### 样式独立发布的实现

第一批只分离主题变量、颜色、字体与已采用变量控制的间距。后续按组件逐步迁移稳定选择器，保留统一设计变量和样式边界检查。

首次接入必须发布一次包含主题入口的模板，并让相关页面采用兼容变量。只有完成接入的页面才能获得后续零 HTML 重建的主题更新；未接入的 Papers、Reports 或历史页面继续使用原有固定样式，面板需要明确显示覆盖范围。

静态 HTML 固定引用主题兼容入口，例如 `theme/compat/v1/theme.css`。该入口是一份小 CSS，通过 `@import` 指向不可变 CSS；完整 CSS 先上传验证，再条件更新入口。一个入口内的引用保持同一代，字体、背景图全部使用不可变 URL。入口使用短缓存，正文、HTML 与 JS 不因兼容主题变化而变化。入口变化不会自动更新已打开页面，下一次加载或刷新生效。

此方案增加一层 CSS 获取，必须测首屏、样式闪动和字体布局偏移。基础结构 CSS 保留在固定资源中，主题不可用时仍有可读布局。只允许同一兼容版本内的样式更新，避免旧页面与新主题不兼容。可变入口不使用固定内容 SRI；需要固定校验的预览和历史快照直接引用不可变 CSS。

Astro scoped CSS、HTML class 变化、CSS 内联、JS 协议变化或工具链升级，保守归为模板发布。不能仅靠文件扩展名判断“只改 CSS”。从共享指纹移除样式前，须证明其不再影响 HTML 字节、资源依赖和组件协议；否则会错误复用页面。

JS 仍按内容哈希固定引用。首阶段不引入可变 JS 引导器；JS 变化更新受影响页面的资源引用和静态 HTML。这样保留现有 hydration 与旧页面兼容性。

### 模板发布与 Papers 兼容

依赖图至少区分内容、主题、模板族、客户端资源、路由与工具链。模板族包括首页、国家、疾病、国家疾病、Situation、研究目录、文章和报告。

国家模板变化只编译对应模块并生成受影响页面。现有 Astro 管线未必能直接完成这一目标，先以隔离入口验证编译方式；必要时使用已验证内容片段进行轻量组装，不能声称修改缓存 key 就消除了 Vite 固定成本。

Papers 新协议分别记录内容、模板和资源摘要；响应缓存键包含这些版本及语言、路径。旧协议继续验证完整 HTML 摘要。新读取器支持双协议后再提交新 catalogue，一次性迁移有完整校验；稳定后，主题变更不再刷新所有正文或逐篇 HTML 摘要。文章、目录和资产仍沿用现有单一 research 发布指针，不另建竞争发布入口。

## 发布一致性与回滚

1. 生成计划，冻结源代码、内容范围、dirty IDs、配置和各目标指针基线。
2. 准备不可变内容、模板和资源，校验 schema、依赖闭包、哈希与兼容性。
3. 上传缺失对象，验证它们可从目标公开路径读取。
4. 对相关通道执行有基线条件的指针更新；冲突时停止，不能用旧候选覆盖新版本。
5. 验证公开入口、样例页面和资源，再确认本任务冻结的 dirty IDs。
6. 保存提交、验证、数据库确认的分阶段收据；提交后崩溃可恢复确认，不重复上传或生成。

Pages 与 R2 不构成一个跨服务原子事务。模板升级采用先扩展兼容性、后更新内容的顺序；旧资源与旧 schema 在过渡期可用。某部分已提交而其他部分失败，面板显示具体提交状态和恢复入口，不能简单显示全部失败或全部成功。

按通道串行提交，兼容的内容与界面准备工作可并行。复用现有任务系统、幂等键、发布基线和收据；同一个指针必须只有一种受控提交机制。自动重试继续使用冻结的候选，不根据新的设置改变已入队任务含义。

回滚恢复已验证的兼容版本组合。内容回滚是一次显式发布事件，不重新标记所有历史 dirty IDs，也不影响其他数据通道；必要的后续重发另建任务。可变 CDN 入口的回滚存在 TTL 窗口，记录回滚提交和公开验证时间。保留旧资源供打开的页面与回滚使用，清理由独立引用分析执行，不作为普通发布步骤。

## 控制面板适配

### 已发现的合同差异

`dashboard/src/features/control-plane/publish.tsx` 与实时发布模块只将 surveillance、situation 列为 JSON 通道；`dashboard/api/routers/publish.py` 的 pending 响应也只提供这两个启用标记。后端服务已存在 literature 独立发布，而 `src/control_plane/publication_kind.py` 将其他 JSON 线归为 `unknown_json`。必须先统一后端合同，再调整前端文案和操作。

`code_only` 目前表示代码发布，不能直接更名为“仅样式”并宣称已获得快速路径。

### 页面组织

保留 `/publish`、`/publish/realtime`、`/publish/tasks`、`/publish/schedules` 入口，按操作目的组织发布首页：

| 区域 | 用户看到的内容与操作 |
| --- | --- |
| 内容发布 | 各通道待发布范围、自动状态、当前线上版本、发布和重试 |
| 界面发布 | 自动识别主题、模板、客户端、路由变更；查看影响范围和发布 |
| 服务用量 | 套餐、账户请求额度、重置时间、各服务消耗、预测和指标更新时间 |
| 发布记录 | 内容、主题、模板版本；耗时、上传量、实际渲染量、失败阶段与回滚 |

默认操作为“检查变更”，返回可审阅的发布计划。日常内容更新不让用户选择 Astro、R2 或构建开关。没有内容变更但存在 CSS 变化时，应允许界面发布。全量重建保留为维护操作，并明确预计影响。

计划摘要示例，数字仅为交互示意：

```text
检测到主题样式变更
影响：主站主题
内容重新生成：0 条
页面重新生成：0 页
资源编译：1 个主题包
Pages 部署：不需要
新增动态路由：0
Worker 请求影响：预计无增加
操作：预览效果 / 发布样式
```

模板变更则明确显示“国家模板，预计生成 N 个页面”；不得仍显示“0 页”。预览固定候选版本，提供中英法、桌面与手机代表页。发布成功指公开验证完成，上传成功仅是中间状态。

### API 与数据模型草案

以下为拟新增合同，不代表现有接口已经支持：

| 接口 | 作用 |
| --- | --- |
| `GET /publish/capabilities` | 返回支持的通道、模式、自动发布与回滚能力、受控原因 |
| `POST /publish/plans` | 只读规划，冻结变更和基线，返回 plan ID、摘要与过期时间 |
| `POST /publish/runs` | 以 plan ID、plan digest 和幂等键创建持久任务 |
| `GET /publish/usage` | 返回后端缓存的套餐、账户及服务用量、数据时间和来源 |
| `POST /publish/rollback-plans` | 计算目标版本的兼容性及影响，执行复用 runs 入口 |

计划包含 `kind`、`channels`、`source_revision`、`input_digest`、`expected_generations`、`affected_templates`、内容与 HTML 数量、资源编译范围、Pages/Worker 部署要求、校验范围和成本估计置信度。模式拟为 `content`、`theme`、`template`、`routing`、`full`；Worker 代码部署作为明确步骤，不伪装成主题发布。

运行收据记录 `content_render_count`、`html_assembly_count`、`template_compile_count`、`uploaded_objects`、`uploaded_bytes`、各阶段耗时、实际提交的版本、公开验证与确认状态。额度 DTO 区分 account totals 与 service breakdown，包含 `plan`、`period_start/end`、`observed_at`、`remaining`、`projected_usage` 和 `status=known|stale|unknown`，不能用新站 PV 替代账户总额。

新前端根据 capabilities 渲染，不再维护硬编码通道列表。旧接口和 `full/reports_only/code_only` 在过渡期由后端适配；没有新能力的服务版本，界面显示现有模式，不虚构快速发布。修改 Pydantic/OpenAPI 后重新生成 `dashboard/src/generated/api`，扩展现有 hooks、任务分类、调度和双语文案。

计划过期、源变化或基线冲突返回可识别错误，前端提示重新检查。后端必须重新验证，按钮禁用不能替代并发保护。内容和主题的自动发布开关独立，暂停某通道不会取消已提交候选的确认恢复。后台重试与手工发布共享同一任务锁与权限机制。

## 实施阶段

| 阶段 | 主要交付 | 退出条件 |
| --- | --- | --- |
| 0 盘点与计划 | 实际套餐和账户用量、生产路由清单、构建阶段基线、统一 capabilities 与只读计划 | 能说明每种发布做什么、为什么、预计影响；文献分类一致 |
| 1 减少数据调用 | 公开 R2 CDN 镜像、缓存/CORS、manifest 客户端直读、旧入口兼容 | 新主站数据请求绕过 Worker，固定版本及错误处理不退化 |
| 2 独立主题发布 | 主题兼容入口、独立 CSS 构建、计划执行、预览与回滚 | 一次颜色或间距修改，内容渲染和 HTML 生成均为 0，Pages 不部署 |
| 3 内容与模板解耦 | 直接生成内容记录、模板族依赖、局部 HTML 投影、Papers 新协议 | 单篇更新不编译全站；国家模板变更不重建文章和报告 |
| 4 收敛与运行验证 | 故障恢复、请求预算、旧客户端指标、端到端回归 | 有可重复的前后数据与可验证回滚，再评估是否退役旧路径 |

第一批可实施任务是阶段 0 的变更分类器、capabilities 和计划预览。随后用首页及国家页的主题变量做小范围试点。控制面板和发布后端在每阶段同时交付，不先做新发布通道再让面板长期显示旧模式。

不默认把 knowledge、reports 或所有研究集合同时迁移。每类先明确内容依赖、SEO 和当前发布契约，再接入统一计划。样式拆分前保留现有正确的缓存失效逻辑。

## 验收与测量

以下为目标，不是本次设计已经运行的测试结果。

| 场景 | 必须满足 |
| --- | --- |
| 兼容主题改色、字体与间距 | 内容记录与 HTML 哈希不变；正文渲染 0；Pages 部署 0；新旧页面可读 |
| JSON 更新 | 当前 HTML 不变；页面新导航显示新数据；已打开页面各组件仍同版 |
| 单篇正文更新 | 只修改该记录及依赖投影；其他记录哈希不变；不运行全站 Vite/Astro |
| 国家模板修改 | 只生成受影响国家页面；文献/报告正文渲染 0；链接和语言切换正常 |
| CDN 绕过验证 | 路由审计与 Cloudflare 请求指标共同确认，不仅凭响应头或缓存命中判定 |
| 额度不可用或已耗尽 | 静态主站和直读数据继续可用；面板显示真实异常；已有动态功能单独报告 |
| 发布中断或竞争 | 未完成候选不可见；旧候选不能覆盖新版本；已提交任务可恢复确认 |
| 回滚与旧页面 | 旧资源可读；回滚后版本与缓存状态可解释；其他通道不被覆盖 |
| 面板滚动升级 | 新旧 DTO 兼容；literature 分类正确；重复点击不产生重复发布 |

至少使用首页、国家、疾病、Situation、研究目录和文章的中英法代表页，覆盖桌面与手机、慢网、跨域、JavaScript 失败、404、损坏 JSON、版本切换和旧标签页。首屏性能使用前后相同条件测量，特别关注主题入口增加的请求、字体布局偏移和数据加载空白。

构建基准区分冷缓存、热缓存和无变化，至少记录多次运行的中位数与范围，拆出规划、内容导出、编译、HTML 组装、校验、上传、指针提交和公开验证。暂不承诺固定秒数；硬性目标是工作范围符合上表，耗时不再因无关正文数量增长。

## 实施前需要核验的部署事实

- Workers 实际套餐、同账户 Papers/订阅/分析等服务的用量，以及指标 API 权限。
- 主站、www、Papers、Reports 和拟用静态域名的生产路由、DNS、缓存规则及 CORS。
- 公开 R2 bucket 是否独立，是否允许绑定自定义域名及设置所需缓存规则。
- 现有完整 HTML、脚本与样式的版本引用，以及必须保留的旧客户端资源范围。
- 常见页面实际经过 Worker 的请求数、当前构建耗时和 Pages 文件预算。

这些核验影响实施参数，不阻碍本设计中的发布分层、计划接口和控制面板合同准备。

本次交付仅新增此设计文档，已检查引用的本地实现路径和文档格式。尚未运行性能基准、读取账户用量或变更生产配置；表中的测试与测量属于实施验收任务。
